# Duet

Плагин Claude Code для разработчиков, которые хотят получать ревью работы Claude от OpenAI Codex. Плагин охватывает небольшие задачи, крупные задачи с планом, исследования и ревью изменений. Каждый вызов Codex записывается в журнал и ограничен лимитом.

[English](README.md) | **Русский**

Duet — независимый проект. Он не связан с Anthropic и OpenAI.

## Что входит

| Команда | Для чего | Меняет файлы? |
| --- | --- | --- |
| `/duet:task` | Небольшое изменение. Субагент `implementer` пишет код, Codex делает ревью, основная сессия делает ревью этапа. | Да, в текущем рабочем каталоге. Коммиты не создаёт. |
| `/duet:feature` | Крупное изменение. Необязательное исследование, план с ревью от Codex, реализация, ревью кода от Codex, итоговое ревью этапа в основной сессии. | Да, по умолчанию в текущем рабочем каталоге; в git worktree на отдельной ветке, если вы об этом попросите. Коммиты и слияние не выполняет. |
| `/duet:research` | Вопрос по кодовой базе. Утверждения с доказательствами, критика от Codex, ответ, в котором разногласия остаются видны. | Нет. |
| `/duet:review` | Второе мнение по ветке или рабочему каталогу. Ревьюер Claude и Codex независимо делают ревью одного и того же состояния, затем основная сессия пишет сводку. | Нет. Для ревью ветки создаётся временный checkout в состоянии detached HEAD внутри каталога запуска. |

Каждая команда также записывает файлы запуска в каталог `.duet/runs/` проекта. Подробнее — в разделе «Как устроен запуск» ниже.

## Требования

- Claude Code (протестировано на версии 2.1.284).
- Codex CLI с выполненным входом. Состояние входа показывает `codex login status`. Протестировано на версии 0.159.2; адаптер использует возможности `codex exec`, которые есть начиная с версии 0.154.
- У вашего аккаунта Codex должен быть доступ к модели по умолчанию `gpt-6-astra` или к другой модели, заданной в настройках.
- Python 3.9 или новее (только стандартная библиотека, устанавливать ничего не нужно) и Git.
- macOS или Linux. Windows без WSL не поддерживается: адаптер использует `fcntl` и группы процессов POSIX. Работа в WSL не тестировалась.
- Проект, в котором запускается Duet, должен быть git-репозиторием хотя бы с одним коммитом.

Каждый запуск расходует ресурсы и Claude, и Codex. Способ оплаты зависит от того, как выполнен вход в каждый CLI: лимиты подписки или оплата API.

## Установка

В сессии Claude Code:

```
/plugin marketplace add SlavaPush/duet-plugin
/plugin install duet@duet-plugin
```

Или из командной строки:

```
claude plugin marketplace add SlavaPush/duet-plugin
claude plugin install duet@duet-plugin
```

Затем перезапустите Claude Code или начните новую сессию. Первый запуск, который ничего не меняет в проекте. Его нужно начать внутри git-репозитория хотя бы с одним коммитом:

```
/duet:research How are the tests in this project organised?
```

Чтобы загрузить локальный checkout плагина только на одну сессию: `claude --plugin-dir /path/to/duet-plugin`.

## Использование

### `/duet:task`

```
/duet:task Add a --version flag to the CLI with a test.
```

Основная сессия записывает в файл `task.md` задачу, критерии приёмки и команды проверки. Команды проверки берутся из файла `.duet.json`; если файла нет, сессия определяет их сама и просит вас подтвердить. Субагент `implementer` меняет код в текущем рабочем каталоге, запускает проверки, получает ревью кода от Codex и исправляет блокирующие замечания. За одно обращение к субагенту выполняется не больше двух раундов исправлений. Затем основная сессия сама повторяет проверки, сверяет каждое блокирующее замечание и возвращает проблемы субагенту, пока остаются вызовы `code-review`. В конце вы получаете изменение в рабочем каталоге и файл `report.md`. Коммит делаете вы.

### `/duet:feature`

```
/duet:feature Add CSV export to the reports page, with tests.
```

Если задача этого требует, сначала проходит этап исследования. По умолчанию работа идёт в текущем рабочем каталоге, как в `/duet:task`. Если вы попросите worktree в запросе («в worktree», «на отдельной ветке») или зададите `"worktree": true` в файле `.duet.json`, основная сессия вместо этого переходит в git worktree с именем по задаче; каталог запуска в любом случае остаётся в исходном checkout. Основная сессия пишет файл `plan.md`, Codex делает ревью плана; план исправляется не больше двух раз. Дальше реализация, проверки, ревью кода и ревью этапа проходят так же, как в `/duet:task`, с учётом плана. В конце вы получаете файл `report.md` и изменение в рабочем каталоге; коммит делаете вы. При работе в worktree вы также получаете путь к нему и имя ветки; слияние выполняете вы.

### `/duet:research`

```
/duet:research Why does the importer parse dates twice?
/duet:research How could we move billing out of the core module, and what are the risks?
```

Основная сессия читает код и документы и пишет файл `research.md`: ответ и пронумерованные утверждения `R-1`, `R-2`, ... У каждого утверждения есть тип: факт, вывод или допущение. Для фактов указаны файлы и номера строк. Codex помечает каждое утверждение как подтверждённое, оспоренное или непроверенное и добавляет свои замечания. В файле `synthesis.md` находятся исправленный ответ, таблица утверждений с итоговой позицией по каждому из них и оставшиеся разногласия. Файлы проекта не меняются.

### `/duet:review`

```
/duet:review --base main --head feature/login
/duet:review --base main
/duet:review --base main --head feature/login https://github.com/acme/app/pull/42
```

С параметром `--head` Duet делает ревью `main...feature/login` во временном checkout в состоянии detached HEAD, а затем удаляет этот checkout. Без `--head` ревью проходит по рабочему каталогу относительно базы, включая неотслеживаемые файлы. Без `--base` базой служит `git merge-base` с основной веткой репозитория. URL merge/pull request добавляет в контекст заголовок, описание и обсуждение; сессия получает их своими инструментами для этого хостинга. Сами изменения всегда берутся из локального git, поэтому сначала загрузите ветку локально. Новый субагент `reviewer` и Codex делают ревью одного и того же состояния и не видят результатов друг друга. В файле `synthesis.md` находятся итоговые замечания с источниками, разногласия, покрытие и вердикт (`findings`, `no_findings` или `inconclusive`). Не меняйте файлы, пока идёт ревью: если рабочий каталог изменится, ревью получит статус `stale`.

## Как устроен запуск

1. **Явные модель и effort.** Каждый вызов Codex использует модель и effort из настроек. Skill никогда не передаёт другие значения и не меняет настройки во время запуска.
2. **Резерв до вызова.** `duet-codex` записывает каждый вызов Codex в журнал запуска до старта Codex и учитывает этот вызов в лимите его этапа.
3. **Необработанные ответы сохраняются.** Необработанный ответ Codex сохраняется, даже если он не соответствует ожидаемой JSON-схеме.
4. **Остановка и вопрос.** Запуск продвигается сам, только если результат полный и непротиворечивый. Вызов с ошибкой, вызов со статусом `stale` и вызов сверх лимита останавливают запуск, и основная сессия задаёт вам вопрос. Автоматических повторов нет. Если ответ не соответствует схеме и рабочий каталог не изменился во время этого вызова, основная сессия может один раз попросить ту же сессию Codex вернуть ответ в нужном формате. Этот запрос учитывается в лимите. В остальных случаях, а также если исправленный ответ по-прежнему не соответствует схеме, запуск останавливается, и основная сессия задаёт вам вопрос.
5. **Независимые ревьюеры.** Каждый ревьюер начинает работу в новой сессии: новый субагент `reviewer`, новая сессия Codex. Ни один ревьюер не видит результат другого. Следующие раунды продолжают ту же сессию Codex, поэтому прежние замечания остаются открытыми, пока их не закроют.
6. **Одно состояние для ревью.** Адаптер вычисляет хеш каталога ревью (HEAD, diff относительно HEAD, неотслеживаемые файлы) до и после каждого вызова Codex и записывает, изменился ли рабочий каталог. Завершённый вызов, во время которого рабочий каталог изменился, получает статус `stale` и не считается одобрением.
7. **Исходные файлы меняет только `implementer`.** Основная сессия пишет исследования, планы, сводки и отчёты, но не код.
8. **Без коммитов.** Duet никогда не создаёт коммиты, не выполняет push и слияние.

Каждый запуск хранится в каталоге `<repo>/.duet/runs/<scenario>-<timestamp>/`, который исключён из git:

- `task.md` — задача в том виде, в каком её поняла сессия; `context/` — внешние материалы, например текст merge/pull request и файлы правил.
- `journal.json` — хронология этапов Claude и вызовов Codex.
- `report.md` (`task`, `feature`) или `synthesis.md` (`research`, `review`) — результат.
- `<stage>-N.json` — разобранные ответы Codex; `<stage>-N.raw.md` — необработанные ответы; `<stage>-N.prompt.md` — собранные prompt.
- `logs/` — логи Codex CLI.

`duet-codex status --run <dir>` выводит хронологию в формате JSON.

## Стоимость и лимиты

Каждый запуск расходует ресурсы Claude и Codex. Способ оплаты зависит от того, как выполнен вход в каждый CLI: лимиты подписки или оплата API. Со стороны Claude работают основная сессия (модель вашей сессии) и субагенты `implementer` и `reviewer` (Opus), все с effort `high`. Со стороны Codex у каждого запуска есть лимит вызовов на этап:

| Этап | Где используется | Вызовов на запуск, по умолчанию |
| --- | --- | --- |
| Ревью плана, `plan-review` | `/duet:feature` | 3 |
| Ревью кода, `code-review` | `/duet:task`, `/duet:feature` | 4 |
| Критика, `critique` | `/duet:research`, `/duet:feature` с исследованием | 2 |
| Ревью merge/pull request, `mr-review` | `/duet:review` | 2 |

По умолчанию вызов, который начинает новую сессию Codex, идёт с effort `xhigh`, а раунд, который продолжает сессию, — с effort `high`. Тайм-аут каждого вызова по умолчанию — 1800 с.

`/duet:feature` — самый дорогой сценарий: до 3 вызовов `plan-review` и до 4 вызовов `code-review`, а также до 2 вызовов `critique`, если в задаче есть исследование. Когда лимит исчерпан, запуск останавливается, и сессия задаёт вам вопрос. Чтобы разрешить больше вызовов в этом запуске, выполните `duet-codex limit --run <dir> --stage <stage> --set N`. Лимиты копируются в журнал при создании запуска, поэтому изменённый лимит в файле `roles.json` действует только для следующих запусков.

## Данные и права доступа

- **Отправляется в OpenAI** через Codex CLI: собранный prompt и всё, что Codex прочитает в каталоге ревью. Собранный prompt состоит из prompt роли, файла `task.md` запуска, материала этапа (план, diff, вывод проверок или исследование) и файлов контекста, например названных наборов правил или текста merge/pull request. Codex работает в sandbox только для чтения (`codex exec --sandbox read-only`) и не может менять файлы.
- **Отправляется в Anthropic**: обычная сессия Claude Code.
- **Хранится на диске** открытым текстом в каталоге `.duet/runs/`: собранные prompt, необработанные и разобранные ответы, логи CLI. Логи CLI содержат ещё одну копию prompt. При первом использовании адаптер добавляет `.duet/` в файл `.git/info/exclude`; ваш файл `.gitignore` не меняется. Каталоги запусков никогда не удаляются автоматически, удаляйте их сами. Не пишите секреты в тексте задачи.
- **Права доступа**: как и любой плагин Claude Code, Duet работает с правами вашего пользователя. У субагента `implementer` есть инструменты `Bash`, `Edit` и `Write`.

## Настройка

Значения по умолчанию из файла `config/roles.json`:

```json
{
  "codex": {"model": "gpt-6-astra"},
  "stages": {
    "plan-review": {"effort": "xhigh", "resume_effort": "high", "limit": 3},
    "code-review": {"effort": "xhigh", "resume_effort": "high", "limit": 4},
    "critique": {"effort": "xhigh", "resume_effort": "high", "limit": 2},
    "mr-review": {"effort": "xhigh", "resume_effort": "high", "limit": 2}
  },
  "timeouts": {"call_seconds": 1800},
  "limits": {"max_log_bytes": 16777216}
}
```

Чтобы переопределить любую часть этих значений, создайте файл `~/.config/duet/roles.json` (`$XDG_CONFIG_HOME/duet/roles.json`, если задана переменная окружения `XDG_CONFIG_HOME`):

```json
{"codex": {"model": "<your-model>"}, "stages": {"code-review": {"effort": "high", "limit": 3}}}
```

- `codex.model` — модель для всех вызовов Codex.
- `stages.<stage>.effort` — effort вызова, который начинает новую сессию Codex; `resume_effort` — effort раунда, который продолжает сессию; `limit` — число вызовов на запуск. Допустимые значения effort: `minimal`, `low`, `medium`, `high`, `xhigh`.
- `timeouts.call_seconds` — тайм-аут одного вызова Codex.
- `limits.max_log_bytes` — наибольший размер лога stdout или stderr одного вызова. Если лог больше, вызов завершается ошибкой.

Неизвестные ключи и недопустимые значения считаются ошибкой.

В файле `~/.config/duet/settings.json` можно задать `rules`: именованные списки Markdown-файлов. Пути указываются относительно каталога этого файла, например `{"rules": {"python": ["rules/python.md", "rules/tests.md"]}}`. Набор правил применяется, только если вы назвали его в запросе.

Необязательный файл `.duet.json` в проекте задаёт команды проверки для `/duet:task` и `/duet:feature` и может включить worktree по умолчанию для `/duet:feature` в этом проекте: `{"checks": ["npm test", "npm run lint"], "worktree": true}`.

Роли Claude работают с effort `high`. Это значение задано в frontmatter файлов skill и агентов. Переменная окружения `CLAUDE_CODE_EFFORT_LEVEL` переопределяет это значение.

## Решение проблем

`duet-codex` — это файл `bin/duet-codex` в каталоге плагина. В сессии Claude Code с включённым Duet сессия вызывает `duet-codex` по имени. `duet-codex call` и `duet-codex wait` обычно выводят одну строку JSON с полем `error`. Ошибки до начала вызова, например исчерпанный лимит или ошибка в файле `roles.json`, выводятся в stderr с префиксом `duet-codex:`.

| Код возврата | Значение | Что делать |
| --- | --- | --- |
| 0 | `completed`: ответ соответствует схеме и сохранён. Это не одобрение. | Прочитайте результат по пути из поля `result` и проверьте вердикт: `pass`, `changes_requested` или `needs_human`. В результате `critique` вместо вердикта есть оценки утверждений. |
| 1 | `failed`: ошибка Codex CLI, тайм-аут или ошибка адаптера. | Прочитайте поле `error` и логи в каталоге `<run>/logs/`, устраните причину, затем попросите повторить вызов. |
| 2 | `invalid`: ответ не соответствует схеме. | Прочитайте файл `<stage>-N.raw.md`. |
| 3 | Лимит этапа исчерпан. | Посмотрите вывод `duet-codex status --run <dir>`. Если нужны ещё вызовы, поднимите лимит командой `duet-codex limit`. |
| 4 | `running`: вызов с `--background` ещё не завершился. | Снова выполните `duet-codex wait --run <dir> --event N`. |
| 5 | `stale`: файлы в каталоге ревью изменились во время вызова. | Прекратите правки и запустите ревью заново. |

- Вход в Codex не выполнен: выполните `codex login`. Состояние входа показывает `codex login status`.
- Модель недоступна вашему аккаунту: задайте `codex.model` в файле `~/.config/duet/roles.json`.
- `Timeout after 1800s`: увеличьте `timeouts.call_seconds`.
- `Process log size limit exceeded`: увеличьте `limits.max_log_bytes`.
- `Cannot start codex`: установите Codex CLI и убедитесь, что `codex` есть в `PATH`.
- Прерванный вызов (Ctrl+C или `SIGTERM`) всё равно получает итоговый статус в журнале. Обычно это `failed`. Если прерывание пришлось на итоговое вычисление хеша рабочего каталога после ответа, который соответствует схеме, статус будет `stale`. Вызов без `--background` после прерывания завершается без строки JSON. Записанный статус показывает команда `duet-codex status --run <dir>`, а для фонового вызова — также `duet-codex wait`.
- Логи вызова N этапа: `<run>/logs/<stage>-N.stdin.txt` (prompt в том виде, в каком он отправлен), `<stage>-N.stdout.log` (события Codex в формате JSON), `<stage>-N.stderr.log` и `<stage>-N.worker.log` для фонового вызова.
- `duet-codex status --run <dir>` выводит каждый этап и каждый вызов со статусом, путями к результатам и ошибкой.

## Обновление и удаление

- Обновление: `claude plugin marketplace update duet-plugin`, затем `claude plugin update duet@duet-plugin`. Чтобы обновление вступило в силу, перезапустите Claude Code.
- Удаление: `claude plugin uninstall duet@duet-plugin`, затем `claude plugin marketplace remove duet-plugin`.

После удаления остаются: каталоги `.duet/` в ваших проектах и строка `.duet/` в их файлах `.git/info/exclude`; каталог `~/.config/duet/`, если вы его создали; worktree и ветки, которые создала команда `/duet:feature`, если вы просили worktree (их показывает `git worktree list`).

## Разработка

Тесты запускаются командой `python3 -B -m unittest discover -s tests -v`. Тесты работают без сети и используют фиктивный исполняемый файл `codex`. Манифесты валидирует команда `claude plugin validate . --strict`. Контрольный список ручного тестирования с настоящими CLI находится в файле [docs/smoke.md](docs/smoke.md). Архитектура и принятые решения описаны в файле [docs/design.md](docs/design.md). Правила, которым следует каждый skill, описаны в файле [protocol.md](protocol.md).

```
.claude-plugin/        plugin.json, marketplace.json
.github/workflows/     tests.yml
agents/                implementer.md, reviewer.md
bin/                   duet-codex
config/                roles.json
docs/                  design.md, smoke.md
lib/duet_codex/        the adapter's Python package
prompts/               role prompts sent to Codex, one per stage
schemas/               review.json, critique.json
skills/                task/, feature/, research/, review/
tests/                 unittest suite and fake_codex.py
```
